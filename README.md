# RescueOS — Live-образ для системного администратора и реаниматора

**RescueOS** — это минималистичный Live-образ на базе Ubuntu 24.04 LTS (Noble), предназначенный для диагностики, восстановления системы и настройки сетевого оборудования. Образ полностью настраивается через bash-скрипт сборки, поддерживает русскую локализацию, статическую сеть с несколькими IP, встроенный DHCP-сервер (dnsmasq), предустановленные сетевые утилиты и Python-пакеты для автоматизации.

> ⚠️ **Внимание:** образ собирается в окружении обычного пользователя с правами `sudo`. После сборки вы получаете ISO-файл, который можно записать на флешку и загрузить на любом x86_64-совместимом компьютере.

## 📦 Что входит в образ

### Системные утилиты
- `aria2`, `curl`, `wget`, `ftp`, `rsync` – загрузка и синхронизация
- `netcat-openbsd` (`nc`), `socat` – сетевая отладка
- `openssh-server` – удалённый доступ
- `parted`, `fdisk`, `e2fsprogs`, `dosfstools` – работа с разделами
- `smartmontools` (`smartctl`) – диагностика дисков
- `grub-pc`, `grub-efi`, `os-prober` – восстановление загрузчика
- `iwd`, `systemd-networkd` – современное управление сетью
- `far2l` – файловый менеджер (Far Manager clone)
- `nano`, `less`, `jq`, `sqlite3` – работа с текстом, JSON, базами
- `usbip` / `usbipd` (**USB/IP**) – проброс USB по сети. В Ubuntu **нет пакета `usbip`**:
  утилиты приходят из `linux-tools-common` (обёртки) и `linux-tools-generic` (сами бинарники),
  модули ядра `vhci-hcd`, `usbip-core`, `usbip-host` – из `linux-modules-extra-*`
- `python3`, `pip3` и предустановленные модули: `requests`, `paramiko`, `psutil`

### Файловые системы Windows
- Поддержка **NTFS** (`ntfs-3g`, `ntfs3`), **exFAT** (`exfatprogs`), **FAT32** (`dosfstools`)

### Сеть
- Статическая настройка с **двумя IP-адресами** на одном интерфейсе (по умолчанию `192.168.137.110/24` и `192.168.0.110/24`)
- Готовый конфиг для **DHCP-сервера (dnsmasq)** для подсети `192.168.137.0/24` (запуск вручную)
- Подсказки по добавлению дополнительных IP и маршрутов в приветственном сообщении
- **Wi-Fi RTL8192EU**: сторонний драйвер `8192eu` (DKMS) уже в образе, встроенный `rtl8xxxu` отключён

### Пользователи и локализация
- Имя хоста: `rescuebox`
- Основной пользователь: `rescue` / пароль `rescue`
- Root: `rescue`
- Русская консоль (`ru_RU.UTF-8`), шрифт `cyr-sun16`, раскладка `us,ru`

### Кастомизация
- Все пользовательские файлы из `~/my_custom_files` копируются в `/home/rescue/` в образе
- Возможность легко добавить свои скрипты, конфиги или утилиты

## 🛠️ Требования к хост-системе для сборки

- **ОС:** Ubuntu 22.04 / 24.04 (или Debian 12+ с установленным `bash`)
- **Пользователь:** обычный, с доступом `sudo`
- **Свободное место:** минимум 8 ГБ
- **Интернет:** для загрузки пакетов Ubuntu (только во время сборки). Доступ к GitHub **не обязателен** —
  исходники драйвера Wi-Fi можно положить в папку `rtl8192eu/` рядом со скриптом
- **Пакеты:** будут автоматически установлены скриптом (`debootstrap`, `xorriso`, `squashfs-tools`, `grub-*`, `mtools`, `aria2`, `git`)

## 📥 Сборка образа

	1. **Скачайте скрипт** `build.sh` и сделайте его исполняемым:
   ```bash
   chmod +x build.sh
	2. Отредактируйте переменные в начале файла (по желанию):

## 📶 Wi-Fi: сторонний драйвер rtl8192eu

В образ **уже встроен** сторонний драйвер `8192eu` (Realtek RTL8192EU, USB). Ваш ручной
рецепт (`apt install dkms build-essential` → `git clone` → `dkms add/install` → `modprobe 8192eu`)
выполняется автоматически во время сборки:

- исходники `clnhub/rtl8192eu-linux` (тег `5.11.2.3`) берутся **из локальной папки или из кэша**,
  сеть нужна только при самой первой сборке (см. ниже);
- модуль собирается в chroot через **DKMS** и попадает в `filesystem.squashfs`;
- встроенный драйвер ядра `rtl8xxxu` (претендует на те же USB-ID) отключается
  файлом `/etc/modprobe.d/rtl8xxxu-blacklist.conf`;
- включается `CONFIG_WIFI_MONITOR=y` — работает режим монитора для `airmon-ng`/`airodump-ng`;
- компилятор (`gcc`, `build-essential`) после сборки модуля удаляется, чтобы не раздувать образ.

### Откуда берутся исходники драйвера

Скрипт ищет исходники в таком порядке (первое сработавшее — используется):

1. **Папка `rtl8192eu/` рядом с `build.sh`** — если она есть, GitHub вообще не нужен.
   Внутри должен лежать `dkms.conf` (корень архива драйвера).
   Распакованный ZIP с вложенной папкой (`rtl8192eu-linux-5.11.2.3/`) тоже распознаётся.
2. **Кэш `.rtl8192eu-src/` рядом со скриптом** — остаётся после первой успешной сборки,
   поэтому повторные сборки работают без интернета.
3. **`git clone`** — только если ни папки, ни кэша нет.

Если GitHub недоступен (частая проблема), просто скачайте архив драйвера на другой машине
и распакуйте рядом со скриптом:

```
ubuntu-rescue-image/
├── build.sh
└── rtl8192eu/          <-- корень архива драйвера (dkms.conf, Makefile, core/, hal/, ...)
```

Ссылка: **https://github.com/clnhub/rtl8192eu-linux** → ветка `5.11.2.3` → `Code` → `Download ZIP`.

Альтернатива — указать путь явно:

```bash
RTL8192EU_SRC_LOCAL=/путь/к/rtl8192eu ./build.sh
```

### Переменные сборки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `RTL8192EU_ENABLE` | `yes` | вкл/выкл встраивание драйвера |
| `RTL8192EU_REPO` | `https://github.com/clnhub/rtl8192eu-linux.git` | репозиторий драйвера |
| `RTL8192EU_REF` | `5.11.2.3` | ветка/тег/коммит (воспроизводимость сборки) |
| `RTL8192EU_MONITOR_MODE` | `yes` | `CONFIG_WIFI_MONITOR=y` (режим монитора) |
| `RTL8192EU_BLACKLIST` | `rtl8xxxu` | встроенный драйвер-конкурент |
| `RTL8192EU_PURGE_BUILD_TOOLS` | `yes` | удалить `gcc`/`build-essential` после сборки |
| `RTL8192EU_REQUIRED` | `yes` | прервать сборку, если драйвер не собрался |
| `RTL8192EU_SRC_LOCAL` | — | путь к локальной копии исходников (сборка без GitHub) |
| `RTL8192EU_SRC_HOST` | `<каталог скрипта>/.rtl8192eu-src` | где хранить кэш исходников |

> ⓘ Имя пакета DKMS и имя модуля (`rtl8192eu` / `8192eu`) скрипт читает из `dkms.conf`
> скачанных исходников, поэтому другой форк драйвера тоже соберётся без правок скрипта.

### Проверка в загруженном образе

```bash
lsusb | grep -i realtek           # адаптер на месте (например, 0bda:818b)
wifi-rtl8192eu                    # перезапустить драйвер и показать состояние
lsmod | grep -E '8192eu|rtl8xxxu' # должен быть 8192eu, rtl8xxxu — отсутствовать
lshw -c network | grep driver     # driver=8192eu
dkms status                       # rtl8192eu/1.0, <версия ядра>: installed
dmesg | grep -i 8192              # сообщения драйвера
nmcli device wifi list            # список сетей через NetworkManager
```

> ⚠️ **Secure Boot** должен быть выключен: ISO собирается `grub-mkrescue` без подписи shim,
> поэтому на машине с включённым Secure Boot флешка вообще не загрузится. Неподписанный
> DKMS-модуль при выключенном Secure Boot грузится нормально. Если Secure Boot обязателен —
> нужна подпись модуля своим ключом и `mokutil --import` (вне рамок этого образа).

> ⓘ Если встроенный `rtl8xxxu` нужен для **другого** адаптера — удалите
> `/etc/modprobe.d/rtl8xxxu-blacklist.conf` в live-системе или пересоберите образ

## 🌐 Роутер: раздача интернета из Wi-Fi в проводную сеть (IPv4)

Образ умеет работать маршрутизатором: **WAN = Wi-Fi** (подключение с default-маршрутом),
**LAN = проводной интерфейс** (статика, `192.168.137.110/24` и остальные адреса из
`STATIC_IPS`). Включается автоматически при загрузке, если Wi-Fi-интернет уже есть:

- **NAT** (`MASQUERADE`) проводной подсети `192.168.137.0/24` в Wi-Fi-интерфейс;
- **DHCP-сервер** (dnsmasq): клиенты получают адреса `192.168.137.50–150`,
  шлюз и DNS = `192.168.137.110`, маска `/24`;
- **DNS-прокси**: dnsmasq слушает на LAN-интерфейсе и пересылает запросы наружу
  (резервный форвард на `8.8.8.8` прописан явно);
- IPv6 не трогается вовсе (только IPv4);
- сетевой сервис `dnsmasq` в системе отключён — используется отдельный экземпляр
  со своим конфигом (`/run/rescue-dnsmasq.conf`), конфликтов с resolved нет.

Управление (автозапуск делает systemd-юнит `rescue-router.service`, ждёт до 3 минут
появления Wi-Fi-интернета и проводного LAN):

```bash
router status   # состояние, интерфейсы, правило NAT
router start    # включить вручную (если автозапуск не сработал)
router stop     # выключить: снять NAT, остановить DHCP/DNS
router restart
```

Лог: `/var/log/rescue-router.log`. Проверка клиента в проводной сети:
получить адрес по DHCP и `ping 8.8.8.8`.

> ⓘ LAN определяется как проводной интерфейс, на котором назначен `192.168.137.110`;
> WAN — беспроводной интерфейс с default-маршрутом. Если оба условия не выполнены,
> `router start` тихо завершается (ничего не ломает) — можно запустить позже вручную.

> с `RTL8192EU_ENABLE=no`.
